# KubeMetal E2E 테스트 시나리오

> 대상 머신: macOS Apple Silicon (64GB Unified Memory)
> 소요 시간: 약 30~50분 (모델 다운로드 네트워크 속도에 따라 변동)

---

## 사전 준비 (공통)

| 단계 | 탭 | 작업 |
|---|---|---|
| 1 | 대시보드 | **[클러스터 시작]** → K3s 기동 확인 (녹색 dot) |
| 2 | 대시보드 | **[스택 프로비저닝]** → MLflow·SeaweedFS 파드 Ready 확인 |
| 3 | 접근 콘솔 | **[포트포워딩 시작]** → 5001(MLflow), 8333(S3), 8888(Filer) 도달 확인 |
| 4 | MLX 스튜디오 | MLX 환경 카드 "설치됨" 자동 표시 확인 (앱 시작 시 자동 체크) |

---

## 시나리오 1: 모델 다운로드

**목적**: HuggingFace에서 경량 MLX 모델을 다운로드하여 로컬 디스크에 배치

| # | 탭 | 실행 | 예상 결과 |
|---|---|---|---|
| 1-1 | 모델 허브 | 카테고리 칩 **[경량 (~3B)]** 클릭 | `mlx-community` 3B급 4bit 모델 목록 표시 |
| 1-2 | 모델 허브 | **`mlx-community/Qwen2.5-0.5B-Instruct-4bit`** 옆 **[다운로드]** 클릭 | 다운로드 진행바 표시, 파일 수 카운트 증가 |
| 1-3 | 모델 허브 | 다운로드 완료 대기 (~1분) | "로컬 모델" 카드에 `Qwen2.5-0.5B-Instruct-4bit` 항목 표시, 용량(~350MB) 확인 |

**✅ 확인 포인트**
- `~/.kubemetal/models/mlx-community__Qwen2.5-0.5B-Instruct-4bit/` 디렉토리 존재
- 파이프라인 탭 스테이지 카드 "모델 준비" → 녹색 dot, "1개 모델 준비됨"

---

## 시나리오 2: RAG 데이터 수집 & 인덱싱

**목적**: 프로젝트 문서를 벡터 DB에 인덱싱하고 시맨틱 검색이 동작하는지 확인

### 2-A: 로컬 문서 인덱싱 (RAG 카드)

| # | 탭 | 실행 | 예상 결과 |
|---|---|---|---|
| 2-1 | 데이터 | RAG 카드 문서 경로에 **`docs`** 입력 (기본값) | 프로젝트 `docs/` 폴더의 마크다운 파일 대상 |
| 2-2 | 데이터 | **[인덱싱 시작]** 클릭 | 진행 표시 → "인덱싱 완료 (N건)" 메시지 |
| 2-3 | 데이터 | 시맨틱 검색 창에 `"Prefect 오케스트레이션 구조는?"` 입력 → **[검색]** | 유사 문서 구절 3건 + Score(거리) 표시 |

### 2-B: 데이터 수집 DAG (Web URL)

| # | 탭 | 실행 | 예상 결과 |
|---|---|---|---|
| 2-4 | 데이터 | DAG 카드에서 소스 타입 **[Web URL]** 선택 | URL 입력 필드 활성화 |
| 2-5 | 데이터 | URL에 `https://mlx-community.github.io/mlx-lm/` 입력 → **[수집 시작]** | 4노드 DAG 순차 실행: Extract → Clean → LanceDB → DVC(선택) |
| 2-6 | 데이터 | DAG 노드 각각 녹색 완료 확인 | 콘솔 로그에 처리 건수 표시 |

**✅ 확인 포인트**
- `~/.kubemetal/lancedb/` 디렉토리에 벡터 인덱스 파일 생성
- 시맨틱 검색 결과에 `mlx-lm` 관련 내용이 포함

---

## 시나리오 3: 학습 전 — 베이스 모델 서빙 & 챗 테스트

**목적**: 파인튜닝 **전** 베이스 모델의 응답 품질을 기록해두고, 학습 후 비교할 기준선(baseline)을 만듦

| # | 탭 | 실행 | 예상 결과 |
|---|---|---|---|
| 3-1 | MLX 스튜디오 | 서빙 카드에서 모델 **`Qwen2.5-0.5B-Instruct-4bit`** 선택, 포트 `8080` | 모델 경로 자동 입력 |
| 3-2 | MLX 스튜디오 | **[서빙 시작]** 클릭 | "서빙 중 (PID XXXXX)" 녹색 표시, 챗 플레이그라운드 활성화 |
| 3-3 | MLX 스튜디오 | 챗 플레이그라운드에서 아래 3개 질문 순서대로 입력: | |
| | | ① `"KubeMetal이 뭐야?"` | 베이스 모델이므로 KubeMetal을 모름 → 일반적/부정확한 답변 |
| | | ② `"macOS에서 MLX로 파인튜닝하는 방법은?"` | 일반적인 MLX 설명 (프로젝트 문맥 없음) |
| | | ③ `"Prefect 오케스트레이션과 MLflow 연동을 설명해줘"` | 일반론 수준 답변 |
| 3-4 | MLX 스튜디오 | **RAG 스위치 ON** 상태에서 ③ 동일 질문 재입력 | RAG 문맥 주입 배지 표시, docs/ 내용 기반 답변으로 품질 향상 |
| 3-5 | MLX 스튜디오 | **[서빙 정지]** 클릭 | 서빙 종료 확인 |

**✅ 확인 포인트**
- 베이스 모델은 KubeMetal 고유 지식을 모름 (예상대로)
- RAG ON 시 프로젝트 문서 기반 답변으로 품질 차이 확인

> 💡 **팁**: 각 응답을 복사(📋 버튼)하여 메모장에 붙여넣기 — 학습 후 비교에 활용

## 시나리오 4: MLX 파인튜닝 실행

**목적**: 경량 모델을 프로젝트 데이터로 LoRA 파인튜닝하여 어댑터 생성

| # | 탭 | 실행 | 예상 결과 |
|---|---|---|---|
| 4-1 | MLX 스튜디오 | 파인튜닝 카드에서 모델 **`Qwen2.5-0.5B-Instruct-4bit`** 선택 | 모델 경로 자동 입력 |
| 4-2 | MLX 스튜디오 | **데이터 경로**: `~/.kubemetal/datasets/sample` (또는 준비된 JSONL 경로) | |
| 4-3 | MLX 스튜디오 | **반복 횟수**: `100` (데모용 단축) | |
| 4-4 | MLX 스튜디오 | **[학습 시작]** 클릭 | PID 할당, iteration 진행바, loss 수치 실시간 갱신 |
| 4-5 | MLX 스튜디오 | 가드레일 카드 확인 | 배터리 잔량, GPU 온도, 메모리 사용량 모니터링 |
| 4-6 | MLX 스튜디오 | 학습 완료 대기 (~5분) | "학습 완료" 녹색 표시, 어댑터 경로 표시 (예: `~/.kubemetal/adapters/...`) |

**✅ 확인 포인트**
- 파이프라인 탭 "학습" 스테이지 → 녹색 dot, "학습 완료"
- loss가 초기값(~2.5)에서 감소 추세 확인
- 어댑터 파일 디렉토리 존재: `adapters.safetensors`, `adapter_config.json`

---

## 시나리오 5: 학습 후 — 어댑터 서빙 & 비교 테스트

**목적**: 파인튜닝된 어댑터를 적용한 서빙에서 응답 품질이 개선되었는지 확인

| # | 탭 | 실행 | 예상 결과 |
|---|---|---|---|
| 5-1 | MLX 스튜디오 | 서빙 카드에서 모델 선택 + **어댑터 경로**에 4-6에서 생성된 경로 입력 | |
| 5-2 | MLX 스튜디오 | **[서빙 시작]** (포트 `8080`) | "서빙 중" + "adapter ..." 표시 |
| 5-3 | MLX 스튜디오 | 시나리오 3과 **동일 3개 질문** 입력 (RAG OFF): | |
| | | ① `"KubeMetal이 뭐야?"` | 학습 데이터에 따라 더 정확한 답변 기대 |
| | | ② `"macOS에서 MLX로 파인튜닝하는 방법은?"` | 프로젝트 문맥 반영 답변 |
| | | ③ `"Prefect 오케스트레이션과 MLflow 연동을 설명해줘"` | 구체적 답변 개선 확인 |
| 5-4 | MLX 스튜디오 | **RAG ON** + ③ 동일 질문 | RAG + 파인튜닝 시너지 → 최고 품질 답변 |

### 5-B: 자동 평가 (선택)

| # | 탭 | 실행 | 예상 결과 |
|---|---|---|---|
| 5-5 | 파이프라인 | Prefect 카드 **[평가(lm-eval) 실행]** 클릭 | gsm8k 자동 채점 시작 |
| 5-6 | 파이프라인 | 완료 대기 (~10분) | exact_match 점수 표시 |
| 5-7 | 접근 콘솔 | **MLflow UI** 클릭 (http://localhost:5001) | `kubemetal-eval` experiment에 점수 기록 확인 |

**✅ 확인 포인트**
- 학습 전 vs 학습 후 답변 품질 차이 체감
- RAG OFF vs RAG ON 답변 품질 차이 체감
- (선택) lm-eval 정량 점수 기록

## 결과 비교 매트릭스

| 질문 | 베이스 (RAG OFF) | 베이스 (RAG ON) | 파인튜닝 (RAG OFF) | 파인튜닝 (RAG ON) |
|---|---|---|---|---|
| KubeMetal이 뭐야? | ❌ 모름 | ⚠️ 문서 기반 부분 답변 | ⭕ 학습 데이터 기반 | ✅ 최고 품질 |
| MLX 파인튜닝 방법은? | ⚠️ 일반론 | ⭕ docs 기반 구체화 | ⭕ 프로젝트 문맥 | ✅ 최고 품질 |
| Prefect+MLflow 연동? | ⚠️ 일반론 | ⭕ docs 기반 구체화 | ⭕ 프로젝트 문맥 | ✅ 최고 품질 |

> **핵심 인사이트**: 파인튜닝은 모델의 "기본 지식"을 개선하고, RAG는 "최신/특정 문서 지식"을 실시간 주입합니다. 둘을 함께 사용하면 시너지 효과가 극대화됩니다.

## 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| 서빙 시작 후 챗에서 오류 | mlx_lm.server 기동 지연 | 5~10초 대기 후 재시도 |
| RAG 검색 결과 0건 | 인덱싱 미수행 또는 경로 오류 | 데이터 탭 RAG 카드에서 인덱싱 재실행 |
| 파인튜닝 loss 감소 안함 | 학습 데이터 형식 불일치 | JSONL `{"text": "..."}` 형식 확인 |
| 포트포워딩 끊김 | Colima VM 재시작 필요 | 접근 콘솔에서 포워딩 재시작 |
| 가드레일 "배터리 부족" | 충전 중 20% 미만 | 충전기 연결 후 [재개] |
