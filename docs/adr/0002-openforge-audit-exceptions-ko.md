# ADR-0002: OpenForge 감사 예외

- 상태: 채택됨 (Accepted)
- 날짜: 2026-09-08

## 배경 (Context)
OpenForge 포트폴리오 감사기(auditor)는 이 저장소를 공유 컴플라이언스 루브릭으로
채점한다. OpenForge ADR-0012(의도적 이탈은 문서화되고 시한이 있어야 하며 조용히
영구화되어서는 안 된다)에 따라, 두 항목은 미완료 갭이 아니라 실제적이고 타당한 이유가
있는 표준과의 차이를 반영한다 — 파일만 추가해 이 항목들을 종료하면 이 저장소가 실제로
운영되는 방식을 왜곡하게 된다.

## 결정 (Decision)
컴플라이언스 형태만 갖춘 거짓 변경 대신, 두 가지 의도적이고 시한이 있는 예외를
기록한다:

**DOC-004 — 언어 짝 문서 비율.** `docs/`의 문서 59개 중 2개만 한국어 짝이 있다
(`docs/architecture.md`를 `docs/architecture-ko.md`와 짝지으면 60개 중 3개). `docs/01`
~`docs/04`와 번호가 매겨진 설계 문서들은 활발한 개발 중 매주 바뀌는 메인테이너 대상
한국어 작업 문서로, 매 수정마다 번역하면 독자에게 이득 없이 즉시 낡은 내용이 된다.
실제로 사용자 대상인 표면 — README, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, 그리고
모든 ADR — 은 이미 완전히 짝지어져 있다. 계획: 새 진입점 문서는 계속 짝을 유지하고
(`architecture.md`는 지금 완료), 작업 문서는 안정화된 뒤에 번역한다.

**I18N-001 — UI 로케일 리소스 디렉터리.** `locales/`, `messages/`, `i18n/` 리소스
디렉터리가 없고 `next-intl`/`react-i18next`/`vue-i18n`/`i18next` 의존성도 없다. UI
문자열은 이미 인코드 사전(`src/i18n/translations.ts` + `src/i18n/i18nContext.tsx`, 약
750개 키)을 통해 `ko`와 `en` 양쪽으로 제공되며, 이는 런타임 리소스 로딩이 필요 없는
단일 데스크톱 Tauri 앱에 적합하다. 계획: 세 번째 언어나 외부 번역가 워크플로가
등장하면 재검토한다 — 그때에야 리소스 파일 형식의 추가 복잡도가 정당화된다.

두 예외 모두 검토일은 **2026-12-31**이다.

## 결과 (Consequences)
- OpenForge 감사는 검토일까지 DOC-004와 I18N-001에서 만점 미만을 계속 기록한다 —
  이는 키워드로 메꿔 닫은 것이 아니라 의도적으로 추적되는 갭이다.
- 2026-12-31에 감사기를 다시 실행하고, 갱신된 근거로 이 ADR을 갱신하거나 실제 작업을
  완료해 예외를 종료한다.
